## 2023-11-01 - Replace countDocuments with limit + 1 pagination pattern
**Learning:** For infinite scroll endpoints (like feed or search), calling `countDocuments` on a MongoDB collection just to determine the `hasMore` flag or the total count is extremely expensive at scale, resulting in an O(N) database operation that significantly degrades performance on large datasets.
**Action:** Always prefer the "limit + 1" pagination pattern for infinite scroll implementations. Query for `limit + 1` documents, check if the returned array length is greater than `limit` to determine `hasMore`, and pop the extra document before returning the response. Avoid fetching total counts unless absolutely required for the UI (e.g., standard page-based navigation), and hardcode a dummy `total` if maintaining a legacy API contract is required.
