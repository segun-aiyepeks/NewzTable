## 2024-03-24 - [Avoid `countDocuments` for Pagination]
**Learning:** The backend API utilizes a 'limit + 1' pattern for pagination queries to determine 'hasMore' boolean flags for infinite scroll, deliberately avoiding expensive O(N) MongoDB `countDocuments()` operations. Removing the 'total' parameter from backend API responses (like search or feed pagination) alters the API contract and constitutes a breaking change. While web and mobile clients only rely on the 'hasMore' flag for infinite scroll, hardcoding `total: 0` to bypass expensive `countDocuments` queries violates the strict rule to 'preserve existing functionality exactly'.
**Action:** Do not remove `countDocuments` if the client expects a `total` field, as this alters the API contract. Either provide `total` as it is, or keep the existing query structure.
