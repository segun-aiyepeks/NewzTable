## 2024-10-12 - Optimize Backend Pagination (Remove countDocuments)
**Learning:** Using `countDocuments` for calculating `total` and `hasMore` in paginated APIs causes a significant performance hit, particularly when coupled with full-text regex searches (which leads to full collection scans). The clients (web and mobile) don't even use the `total` field, making this query completely redundant and a pure waste of database resources.
**Action:** When implementing infinite scroll feeds, fetch `limit + 1` documents instead of using `countDocuments`. If `results.length > limit`, we know there is more data (`hasMore = true`), and we can `pop()` the extra item before returning the response. This cuts the number of database queries in half and completely avoids expensive full-collection count scans for search.
