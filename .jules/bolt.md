## 2024-05-15 - Optimize Pagination APIs
**Learning:** The backend API utilizes a 'limit + 1' pattern for pagination queries to determine 'hasMore' boolean flags for infinite scroll, deliberately avoiding expensive O(N) MongoDB `countDocuments()` operations. Removing the 'total' parameter from backend API responses alters the API contract and constitutes a breaking change. However, web and mobile clients only rely on the 'hasMore' flag for infinite scroll, allowing the total to be safely hardcoded (e.g., `total: 0`) to avoid expensive `countDocuments` queries.
**Action:** Always prefer the 'limit + 1' pattern instead of `countDocuments` for pagination APIs that are consumed by infinite scroll interfaces, and hardcode `total: 0` if the API contract requires a total field but it's not actually used for UI representation.
