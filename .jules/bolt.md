## 2024-05-18 - Avoid countDocuments for Infinite Scroll
**Learning:** `countDocuments` is an O(N) operation in MongoDB and becomes a bottleneck for pagination queries. The backend API utilized a 'limit + 1' pattern for pagination queries to determine 'hasMore' boolean flags for infinite scroll, deliberately avoiding expensive O(N) MongoDB `countDocuments()` operations. Web and mobile clients only rely on the 'hasMore' flag for infinite scroll, allowing the total to be safely hardcoded (e.g., `total: 0`) to avoid expensive `countDocuments` queries without breaking the API contract.
**Action:** When implementing infinite scrolling with MongoDB, use the 'limit + 1' pattern (fetching `limit + 1` documents, setting `hasMore = articles.length > limit`, and discarding the extra item) to avoid `countDocuments` operations completely. Hardcode properties like `total` to 0 or null if exact totals are not required by clients but needed to preserve schema contracts.
